## 📌 Project Overview

**Eclipse Arena** is a fictional digital gaming store designed to provide users with a visually engaging way to discover games, browse different genres, explore promotions, read gaming updates, learn about the platform, and access support information.

The project focused on creating a strong gaming identity while keeping navigation clear and consistent across the website.

The final website contains four main pages:

```text
Eclipse Arena
│
├── Home
├── All Games
├── About
└── Support
```

Each page shares the same core visual language, including a fixed sidebar, dark gaming-inspired interface, teal accent colour, consistent typography, structured sections, and reusable footer/navigation elements.

---

The Home page acts as the main entry point to Eclipse Arena.

## 🎨 Visual Design

Eclipse Arena uses a dark visual style inspired by modern gaming platforms.

### Main Colour Palette

| Colour | Usage |
|---|---|
| `#1de9b6` | Main teal accent, hover states, titles and highlights |
| `#12192b` | Sidebar, cards and secondary dark sections |
| `#0a0f1a` | Main dark background |
| `#e6e6e6` | Primary readable text |
| `#cccccc` | Supporting and secondary text |

The teal accent is repeated throughout the interface to give users consistent visual feedback when interacting with buttons, links, cards, and icons.

---

## 🧩 Design Principles

Several core design principles were applied throughout the project.

### Contrast

Light text and bright teal highlights are placed against dark backgrounds to improve visibility.

### Alignment

Game cards, page sections, navigation elements, and footer content follow structured grid alignment.

### Repetition

Colours, hover effects, typography, buttons, navigation styles, and card layouts are reused across pages to create consistency.

### Proximity

Related information such as game artwork, pricing, and actions is grouped together.

### Balance

The fixed sidebar is balanced against the main content area while individual sections use consistent spacing and layout.

## 📱 Responsiveness

The project was primarily designed as a **desktop front-end website**.

Desktop layouts use structured grids and fixed navigation successfully, but testing identified that the current implementation is **not fully responsive on smaller/mobile screens**.

Some images and content areas can lose their intended proportions or extend beyond the available screen width.

This is documented as a current project limitation rather than presenting the site as fully responsive.

## 🐞 Development Challenges

Several practical front-end problems were identified and solved while developing the project.

### CSS File Paths

After reorganising project folders, CSS paths had to be corrected so each HTML page could locate its stylesheet properly.

### Sidebar Overlap

The fixed sidebar originally overlapped some page content.

Appropriate left spacing was added to keep the main content positioned beside the sidebar.

### Price Tag Positioning

Game-card prices originally appeared beneath the cards rather than over the images.

Relative and absolute positioning were used to correctly anchor price labels at the bottom of each card.

### Footer Layout

An early Flexbox footer did not provide the intended alignment.

The layout was changed to **CSS Grid**, producing four evenly spaced footer columns.

### Hover Styling

A hover selector was initially written incorrectly as a normal class.

Correcting it to the CSS `:hover` pseudo-class restored the expected interaction.

### HTML Structure

Missing closing `</body>` and `</html>` tags were identified and corrected to keep the HTML structure valid and maintainable.
